## ⭐️ant apply

https://platform.claude.com/docs/en/cli-sdks-libraries/cli/apply

一言でいうと **Claude API リソースの Terraform**。agent / environment / skill / memory store / deployment をリポジトリ内のファイルとして書き、`ant apply` で API 側の実体と同期する。Console で手でポチポチ作る代わりに、レビューと git 履歴が効く形にする道具。CLI v1.30.0 以降。

### 最小の例

```markdown
<!-- agents/summarizer.md -->
---
name: Summarizer
model: claude-opus-5
tools:
  - type: agent_toolset_20260401
---

You are a helpful assistant that writes concise summaries.
```

```
ant apply agents/summarizer.md
```

frontmatter が設定、本文が system prompt。terraform の `plan` → `apply` と同じ流れで、いきなり適用せず「何を作る／変えるか」の一覧を出して `y`（適用）/ `n`（中止）/ `d`（フィールド単位の詳細・差分）を聞いてくる。`--dry-run` なら詳細を出して適用せず終了。

### 肝は claude-lock.json

初回 apply がカレントディレクトリに吐くのでリポジトリルートで実行する。中身は「どのファイルがどのリソース ID になったか」＋ organization / workspace。

```json
"./agents/summarizer.md": {
  "kind": "agent",
  "id": "agent_011CYm1BLqPXpQRk5khsSXrs",
  "hash": "d232...",        // 最後に送った内容
  "remote_hash": "1b77..."  // API が返した内容
}
```

これを commit しないと、次の実行が同じリソースを見つけられず**もう1個作る**。役割は terraform.tfstate と同じ（ファイルと実体の対応表）だが、**扱いは逆で、こちらは commit する**。

| | commit するか | なぜ |
| --- | --- | --- |
| terraform.tfstate | しない | 平文の secret が載るので remote backend に置く |
| claude-lock.json | **する** | 載るのは ID とハッシュだけ。credential は入らない |

### 「lock」ファイルなのにロックが無い

名前が紛らわしいが、`claude-lock.json` の lock は `package-lock.json` と同じ**「バージョンを固定する」の lock** で、**排他制御の lock ではない**。terraform の state lock（実行中は他を弾く仕組み）に当たるものが `ant apply` には無い。

無いと何が困るか。ファイル更新は read → modify → write の3ステップなので、その隙間に別プロセスが割り込める:

```
A: lockfile 読む（summarizer は未作成）
B: lockfile 読む（同上）        ← A がまだ書いてないので B にも見えない
A: agent 作成 → agent_AAA / lockfile 書く
B: agent 作成 → agent_BBB / lockfile 書く   ← A の記録を上書き
```

結果、**API 側に agent が 2 つでき、agent_AAA はどのファイルからも参照されない孤児になる**。lockfile を消してしまったときと同じ壊れ方。terraform ならここで 2 本目が `Error acquiring the state lock` で即失敗するが、`ant apply` は黙って通る。

つまり同時実行しない責任は運用側にある。GitHub Actions なら `concurrency` で直列化する:

```yaml
concurrency:
  group: ant-apply
  cancel-in-progress: false   # 適用の途中で殺すと中途半端に作られる
```

### リソース同士は相対パスで参照する

API が ID を要求する場所に、そのリソースのファイルへの相対パスを書く。`ant apply` が依存順に作って実 ID を埋める。

```yaml
# agents/reviewer.md
skills:
  - ../skills/pr-summary
```

```yaml
# deployments/nightly.md
agent: ../agents/reviewer.md
environment_id: ../environments/cloud.yaml
resources:
  - path: ../memory_stores/review-notes.yaml
    access: read_write
```

### ハマりどころ

- **Console や `ant beta:agents create` で作ったものは取り込めない**。lockfile にあるものだけが管理対象で、既存 agent と同じ内容のファイルを apply すると2個目ができる。Console の `Export as code` は lockfile 付きで落ちてくるのでそれなら繋がる
- **ファイル名の変更＝新しいリソースの宣言**。旧リソースは `--prune` するまで残る
- **ファイルを消しても消えない**（警告だけ）。`--prune` でアーカイブ（skill は削除）

### フラグ

| フラグ | 効果 |
| --- | --- |
| `--dry-run` | plan だけ出して終了、lockfile も書かない |
| `--yes` | 確認なしで適用 |
| `--force` | 外部で変更・アーカイブ・削除されていても適用 |
| `--prune` | lockfile にあるが宣言が消えたリソースを削除 |
| `--upgrade` | GitHub URL 参照の skill を再解決 |
| `--lock-file <path>` | 使う lockfile を明示。org / workspace ごとに分ける |


## NeetCode: 8. Valid Sudoku

https://neetcode.io/problems/valid-sudoku/question?list=neetcode150

9×9 の盤面が、行・列・3×3 の箱それぞれで数字が重複していないかを判定する。空マス `.` は無視。埋まっている必要も、解ける必要もない。**今ある数字が矛盾していないか**だけを見る。

まず用語を分けておく。この問題は**数えるものが 2 種類あって、そこが混ざると読めなくなる**。

| | 何か | 個数 |
|---|---|---|
| **マス** | 数字が 1 つ入る最小の枠。座標は `(r, c)` | **81** |
| **箱** | 太線で区切られた 3×3 のかたまり | **9** |

81 マスが 9 個の箱に分かれている（**1 箱に 9 マス**入っていて 9 × 9 = 81）。以降、番号 0〜8 が出てきたら**マスではなく箱を数えている**。

やっていることは 1（Contains Duplicate）と同じ「重複判定」。違うのは**1 マスの数字が 3 つのグループに同時に属している**こと。`board[4][7]` の数字は「4 行目の仲間」であり「7 列目の仲間」であり「箱 5 の仲間」でもある。

```
1 の重複判定:  数字の行き先は1つ  ->  Set 1個
この問題:      数字の行き先は3つ  ->  Set を 行9個 + 列9個 + 箱9個 = 27個
```

だったら**袋を 27 個用意して、1 マスごとに 3 つとも確認する**だけでいい。袋は「グループの数」だけ要るのであって、マスの数（81）は要らない。

```ts
class Solution {
    isValidSudoku(board: string[][]): boolean {
        // 袋はマスの数（81）ではなく「グループの数」だけ用意する
        // 行 0〜8 それぞれに「その行で見た数字を入れる袋」を1つずつ。計9個
        // rows[3] は「3行目に出た数字の集合」という意味になる
        const rows = Array.from({ length: 9 }, () => new Set<string>());
        const cols = Array.from({ length: 9 }, () => new Set<string>()); // 列は9本なので9個
        const boxes = Array.from({ length: 9 }, () => new Set<string>()); // 箱も9個（81個ではない）

        // 上の行から順に、各行を左から右へ。81マスをちょうど1回ずつ見る
        for (let r = 0; r < 9; r++) {
            for (let c = 0; c < 9; c++) {
                const val = board[r][c];
                if (val === '.') continue; // 空マスは何も主張していないので飛ばす

                // 「今いるマスが、9個の箱のうちどれに入っているか」を求める。
                // 箱は9個しかないので b は 0〜8。同じ箱の中の9マスは全員おなじ b になる。
                // 座標 (r, c) は81通りあるが、b はそれを9通りに畳んだもの。
                // この1行だけが本問の考えどころ（詳しくは下で分解する）
                const b = Math.floor(r / 3) * 3 + Math.floor(c / 3);

                // 行・列・箱の3つの袋のどれか1つにでも同じ数字が既にあれば、そこが重複
                if (rows[r].has(val) || cols[c].has(val) || boxes[b].has(val)) return false;

                // なければ3つの袋すべてに登録して次のマスへ
                rows[r].add(val);
                cols[c].add(val);
                boxes[b].add(val);
            }
        }

        // 81マス見終わって一度もぶつからなかった = 有効な盤面
        return true;
    }
}
```

#### `rows[0]` の中身は「1 個の `Set`」

`rows` は **`Set` が 9 個入った配列**。`rows[0]` はその 1 個目の `Set` そのもの。配列のマス 1 つに、`Set` が丸ごと 1 個ずつ入っている（入れ子）。

```
rows = [ Set{} , Set{} , Set{} , Set{} , Set{} , Set{} , Set{} , Set{} , Set{} ]
          ↑0      ↑1      ↑2      ↑3      ↑4      ↑5      ↑6      ↑7      ↑8
       0行目用  1行目用                                                8行目用

盤面を進むと、それぞれの袋が独立に育っていく:
rows[0] = Set{ "5", "3", "7" }        0行目でここまでに見た数字
rows[1] = Set{ "6", "1", "9", "5" }   1行目でここまでに見た数字
```

だから `rows[r].has(val)` は「**r 行目の袋の中に val が入っているか**」を聞いていることになる。

## NeetCode 11. Two Integer Sum II

https://neetcode.io/problems/two-integer-sum-ii/question?list=neetcode150

ソート済みの配列から、足して `target` になる2つの**添字**（1 始まり）を返す。

ソート済みなら、**和が目標より大きいか小さいか**が「どちらの端を動かすか」をそのまま教えてくれる。

```ts
class Solution {
    // 例: numbers = [1, 2, 3, 4], target = 3  ->  [1, 2]
    twoSum(numbers: number[], target: number): number[] {
        let l = 0;
        let r = numbers.length - 1;

        // すれ違ったら終わり。同じ要素は2回使えないので l < r（l <= r ではない）
        while (l < r) {
            const sum = numbers[l] + numbers[r];

            if (sum > target) r--;      // 大きすぎる -> 右端をひとつ小さい値へ
            else if (sum < target) l++; // 小さすぎる -> 左端をひとつ大きい値へ
            else return [l + 1, r + 1]; // 1 始まりなので +1
        }

        return [];
    }
}
```

#### よくある間違い: `r` を巻き戻す

`l` を `for` で回し、`l` が進むたびに `r` を右端へ戻す書き方は、動くが**すべてのペアを試す二重ループ**になっていて O(n²)。捨てた候補を拾い直している時点で、two pointers ではなく総当たり。**ポインタは戻さない**のが型。
