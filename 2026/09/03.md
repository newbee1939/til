## ⭐️Google Cloud API呼び出しにおけるQuota Projectと403エラーについて

### Quota Projectとは

- Google Cloud APIにおいて「どのプロジェクトの利用枠（Quota）としてカウント・課金するか」を決定するプロジェクト
- Google Cloudにおける「APIの有効化」とは、そのプロジェクトを契約者として登録することであり、単なる機能のON/OFFではない
- `403 SERVICE_DISABLED`は、このQuota Project側で対象のAPIが有効化されていない場合に発生する

### API種別によるQuota Project決定ルール

APIの呼び出しには、「リソースの作成先（Target）」と「呼び出し元（Token）」の２つのプロジェクト情報が含まれる。

- `resource-based API`（Compute, GCSなど大部分）
  - リソースの作成先プロジェクトが強制的にQuota Projectになる
  - Target と Quotaが一致するため、権限のズレによるエラーは起きない
- `client-based API`（Discovery Engine, BigQuery Data Transferなど一部）
  - 呼び出し元（認証トークンの所属プロジェクト）がQuota Projectになる
  - リソース作成先でAPIを有効化していても、呼び出し元プロジェクトで未有効化だと`403`エラーになる

### client-based APIでの403解決策

以下のいずれか。

- 呼び出し元（Quota Project側）でもAPIを有効化する
- Provider側でQuota projectを明示的に上書きする（公式推奨）
  - Terraform Providerに`user_project_override = true`を設定し、`X-Goog-User-Project`ヘッダでQuota Projectをリソース作成先のプロジェクトへ強制する
