## Akamai: Force revalidation of state objects

参考: https://community.akamai.com/customers/s/article/Caching-Behaviorrxdxn?language=en_US

エッジサーバがオリジンサーバにStale Object（TTLが期限切れとなったコンテンツ）の有効性を再確認する際の挙動を設定。

- `Serve stale if unable to validate`
    - コンテンツの有効性を再確認出来なかった場合、エッジサーバはStale Objectをクライアントに返却する
- `Always revalidate with origin`
    - コンテンツの有効性を再確認出来なかった場合、エッジサーバはクライアントにエラーを返却する

サイトを（見せかけ上でも）落としたくないのであれば、前者を設定しておけば良さそう。

## ⭐️terraform init時の挙動

### module のダウンロードの流れ

**Registry は倉庫ではなく住所案内所。** モジュールの実体は持っておらず、「そのバージョンの実体はここにあるよ」と `X-Terraform-Get` ヘッダで住所を返すだけ。実体は GitHub などにある。

1. `.tf` から `module` ブロックを集め、`source` の種類を判別する
2. registry なら 3 往復して実体の住所を聞き出す（下の具体例）
3. git / http / S3 は 2 をスキップして直接取得する
4. `.terraform/modules/<key>/` に展開し、`modules.json` に台帳を書く
5. module 内の module は再帰。全部揃ってから provider を解決する

#### 具体例: `terraform-aws-modules/vpc/aws`

```hcl
module "vpc" {
  source  = "terraform-aws-modules/vpc/aws"
  version = "~> 6.0"
}
```

この 2 行で実際に起きること（`source` はホスト省略なので `registry.terraform.io`）:

1. **どこに聞けばいい？** → `GET https://registry.terraform.io/.well-known/terraform.json`

    ```json
    {"modules.v1":"/v1/modules/","providers.v1":"/v1/providers/"}
    ```

2. **どのバージョンがある？** → `GET https://registry.terraform.io/v1/modules/terraform-aws-modules/vpc/aws/versions`

    243 個返ってくる。`~> 6.0` に合う最新として `6.7.2` を選ぶ

3. **実体はどこ？** → `GET https://registry.terraform.io/v1/modules/terraform-aws-modules/vpc/aws/6.7.2/download`

    ```
    HTTP/2 204
    x-terraform-get: git::https://github.com/terraform-aws-modules/terraform-aws-vpc?ref=cf0e3ca...
    ```

    **本文は空（204）**。住所だけ返る。バージョンタグではなく**コミット SHA に解決済み**なのがポイント

4. その GitHub リポジトリを取得し、`.terraform/modules/vpc/` に置く

手元でも同じことを確認できる:

```sh
curl -sD- -o/dev/null https://registry.terraform.io/v1/modules/terraform-aws-modules/vpc/aws/6.7.2/download | grep -i x-terraform-get
```
