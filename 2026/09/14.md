## ⭐️gh auth setup-git

https://cli.github.com/manual/gh_auth_setup-git

> This command configures git to use GitHub CLI as a credential helper.

- Git が GitHub へ push / pull するとき、`gh` のログイン情報で認証するよう設定するコマンド
- credential helper = Git が「ID とトークンちょうだい」と問い合わせる先のプログラム

### メリット

- `gh auth login` しておけば、Git 用に PAT を別で発行・入力しなくていい

### 使わないと毎回入力が必要？

**HTTPS で、helper が何も設定されていない場合だけ毎回入力になる。**

- SSH（`git@github.com:...`）で使っている → 不要（SSH 鍵で認証）
- macOS の `osxkeychain` など別の helper がある → 初回だけ入力、以後は保存済みの値を使う
- 入力するのはパスワードではなく PAT（GitHub は HTTPS でのパスワード認証を廃止済み）
- 確認: `git config --get-all credential.helper`

### なぜ SSH だと PAT 不要で、HTTPS だと必要？

- **SSH**: 事前に GitHub に公開鍵を登録 → 接続時に手元の秘密鍵で「本人の証明」を作って渡す
  - 秘密鍵そのものは送らない。鍵ファイルが手元にあるので、毎回の入力は要らない
- **HTTPS**: 普通の Web 通信と同じで、リクエストに「ユーザー名 + トークン」を載せて本人確認する
  - 何かが手元にトークンを持っていないと送れない → 入力する or helper（keychain / gh）に覚えさせる

## ⭐️terraform plan -minimal-refresh

参考: https://qiita.com/minamijoyo/items/92c094b554d090b54a17

### 公式ドキュメントは？

- **2026-09-14 時点で [plan のリファレンス](https://developer.hashicorp.com/terraform/cli/commands/plan) には未掲載**
- 一次情報は Terraform の CHANGELOG（v1.17.0、未リリース）

> A new `-minimal-refresh` planning option has been added, which will only refresh resources that have proposed changes. ([#35290](https://github.com/hashicorp/terraform/issues/35290))

### 何をする？

- 通常の plan: **全リソース**を refresh（API で実環境の状態を取得）→ リソースが多いと遅い
- `-minimal-refresh`: **変更するリソース（と依存するリソース）だけ** refresh → 速い
  - 記事の検証: 200+ リソースで 45〜50 秒 → 3〜5 秒

### なぜ「ローカルは -minimal-refresh、CI は通常 plan」が無難？

- 変更しないリソースは refresh されない → **コンソールでの手動変更などのドリフトに気づけない**
  - 変更するリソース自体は refresh されるので、今回の apply が壊れるわけではない
- CI の plan は apply 前の最後のレビュー。ここで全体のドリフトを出しておきたい

### CI も速くしたいなら

- PR の CI は `-minimal-refresh` にする
- 代わりに main で**定期的（例: 毎日）に通常の plan** を回し、ドリフト検知はそっちに任せる

## ⭐️Open Policy Agent（OPA）

- 公式サイト: https://www.openpolicyagent.org/
- ドキュメント: https://www.openpolicyagent.org/docs

> オープンソースの汎用ポリシーエンジン。アプリのロジックからポリシー判定を切り離す

### ツールなの？

**ツール。** `opa` という 1 つのバイナリで、CLI / HTTP サーバー / Go ライブラリとして使える。

- アプリが JSON を渡して「これ OK？」と聞く → OPA が **Rego**（専用言語）で書いたルールで判定して返す
- 判定は OPA、実際に止めるのはアプリ側

### どう使う？

- サーバー: アプリが `POST localhost:8181/v1/data/...` で問い合わせ → `{"result": false}` なら 403
  - 毎リクエスト聞くので、同じ Pod（サイドカー）やホストに置く
- CLI: CI で `terraform show -json` をチェック（Conftest）。サーバー不要
- 1 か所の簡単なチェックならアプリの `if` で十分。複数サービスでルールを揃えたいときに効く

### CNCF との関係は？

- CNCF = Kubernetes などを管理する、クラウドネイティブ系 OSS の運営団体
- OPA は CNCF の **Graduated プロジェクト**（成熟度の最上位、2021-01 に到達）
