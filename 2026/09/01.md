## npm install --omit=peer

「`peerDependencies` を自動インストールしない」という指示を出すコマンド。

### 前提

```jsonc
// my-app/package.json ← 自分が書く（使う側）
{ "dependencies": { "react": "18.2.0", "react-datepicker": "^7.0.0" } }
```

```jsonc
// react-datepicker/package.json ← プラグイン作者が書く
{ "peerDependencies": { "react": "^18.0.0" }, "dependencies": { "date-fns": "^3.0.0" } }
```

### `npm install` の流れ

1. package.json を読み、依存の依存…を再帰的に辿って**ツリーを先に組み立てる**（まだDLしない）
2. 全員の条件を同時に満たせなければ `ERESOLVE` で中断（＝1つも入らない）
3. 組み立て通りにDL・展開。**競合しないものは `node_modules/` 直下にまとめる**（平坦化）
4. 確定結果を `package-lock.json` に記録

```
my-app/node_modules/
├── react@18          ← my-app も datepicker もこの1つを使う
├── date-fns@3        ← datepicker の依存。競合しないので直下
└── react-datepicker/
    └── node_modules/ ← 競合したものだけここ（今回は空）
```

- Node は `require('react')` を「自分の `node_modules` → なければ1つ上」と辿って探すので、直下に1つあればどこからでも届く

#### 「競合」とは

- 同じ名前のパッケージで、**互換しないバージョンが同時に必要**になること
- `node_modules/lodash` というディレクトリは1つしか作れないので、片方を直下に、もう片方を**要求した側の配下**に置いて両立させる

```
my-app が lodash@3、datepicker が lodash@4 を要求した場合

node_modules/
├── lodash@3                    ← my-app 用
└── react-datepicker/
    └── node_modules/lodash@4   ← datepicker はこっちを先に見つける
```

### `peerDependencies` とは？

- 「私はこれを前提に動く。**自分では持たないので、使う側が入れたものを使わせて**」という宣言
- `date-fns` は自分専用なので、上のように重複してよい。一方 `react` は**1つを共有しないと壊れる**

Node は「1度読んだファイルはパスをキーにキャッシュし、2度目は評価せずキャッシュを返す」:

```js
// counter.js
let n = 0;
module.exports = { inc: () => ++n };
```

- 2箇所から**同じパス**の `counter.js` を読めば、`n` は同じ1つ（1→2と増える）
- コピーが2つあってパスが違えば、それぞれ別に評価され `n` も別々（両方 1 のまま）
- React の `n` にあたるのが「今どの hooks を処理中か」の状態。react が2つあると噛み合わず `Invalid hook call` になる

### なぜ `--omit=peer` が必要か？

デフォルト（npm v7以降）の挙動:

- 既にある `react` が peer の条件（`^18`）を**満たしていれば何もしない**。勝手に増やしたりはしない
- 足りない・宣言されていないときだけ、npm が自動で入れる（v6以前はここで警告が出るだけだった）
- **満たせないときが問題**。例: my-app が `react@17`、datepicker の peer が `^18` → 両立しないので流れの 2 で `ERESOLVE unable to resolve dependency tree` となり、1つもインストールされない
  - `ERESOLVE` はシステムコールや OS のエラーではなく、**npm が依存解決に失敗したときに自分で付けるエラーコード**（`E` + `RESOLVE`）。`ENOENT` のような OS 由来のコードとは別物
- `--omit=peer` で peer を入れずに通す（実行時の互換は自己責任）。恒久対応は `react` を 18 に上げる、またはプラグインを下げる
- 参考: https://docs.npmjs.com/cli/v11/configuring-npm/package-json#peerdependencies
