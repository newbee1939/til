## ⭐️GitHub Appとは？

外部アプリや自動化ツールにGitHubを連携させるための、"公式推奨の"仕組み。

- 属人化の排除
    - 個人のアカウントに紐付かないため、担当者の退職や移動で連携が壊れない
- コストと手間の削減
    - ダミーのユーザーアカウントを作る必要がなく、ライセンス枠の消費やパスワード管理が不要
- 高い安全性
    - リポジトリ単位で「この操作だけ」という最小限の権限を設定できる

要は、外部システムからGitHubを安全に自動操作させたい場合の最適解。

## git archive

> Git管理下のファイル一式から.gitディレクトリなどを除外して、zipやtar形式のアーカイブを作成できるコマンド

e.g.

```shell
# 最新のコミット（HEAD）をZIPで出力する
git archive --format=zip -o archive.zip HEAD
```

## ⭐️Mergiraf

https://mergiraf.org/

Git のマージコンフリクトを**構文木（AST）ベース**で解決する merge driver。Git 標準は「行」しか見ないが、Mergiraf は言語の文法を理解して両者の変更を突き合わせる。

base に `import json` だけある状態から、2人が別々に import を足す。

```python
# base        # ブランチA      # ブランチB
import json   import json      import json
              import os        import sys
```

Git には「同じ場所に別の行」＝ コンフリクト。Mergiraf は **import が「順序が意味を持たない列挙」だと文法から分かる**ので、両方採って `import json / os / sys` を返す。

### コンフリクトとして認知されなくなる？

ほぼその通り。ただし git が見落とすのではなく:

1. git が行レベルで衝突を検出する
2. `.gitattributes` 経由で merge driver（= Mergiraf）が呼ばれる
3. 解けたら**成功として git に返す** → 人間の目にはコンフリクトが出ない
4. 解けなければ従来どおりマーカーを残す

握りつぶしではなく「driver が代わりに解いた」。3 は `mergiraf review` で後から確認できる。
