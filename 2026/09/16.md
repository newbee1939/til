## ⭐️Agent Router

参考: https://gihyo.jp/article/2026/09/agent-router
参考: https://www.publickey1.jp/blog/26/openaianthropicapiagent_routerlinux_foundation.html

### Agent Routerとは？

AIエージェントとLLM / 外部ツールの間に立つ**ゲートウェイ**。要は **LLM版のリバースプロキシ**。アプリはモデルを直接知らず、ルータ越しに喋る。

Bloomberg + Tetrate が Envoy のサブプロジェクトとして始め、いまは AAIF（Linux Foundation 傘下）の独立プロジェクト。

- OpenAI / Anthropic / Google などAPI形式の違いを **OpenAI互換の1エンドポイント**に統一
- MCPサーバも1エンドポイントに束ね、OAuthで認可をかける（MCP Gateway）
- フォールバック、チーム / アプリ単位の使用量制限、トークン数やレイテンシの可視化

### OpenRouterとの違い

**OpenRouter は「通す先」、Agent Router は「自分で建てる関所」**。

|  | OpenRouter | Agent Router |
| --- | --- | --- |
| 形態 | ホスティング型SaaS | OSS。自分で動かす |
| 通信経路 | OpenRouterを経由（プロンプトが社外へ） | 自社ネットワーク内で完結 |
| キー / 課金 | OpenRouterにクレジット（契約先は1社） | 各ベンダと自分で契約、自分のキー |
| モデル | 数百モデルにすぐ繋がる | 自分が契約したものだけ |
| ガバナンス | 利用量の可視化まで | 認可・MCPゲートウェイ・チーム単位の制限 |

### どういう場面で使うか？

- モデルを差し替えたいが、アプリのコードは書き換えたくない（ロックイン回避）
- 複数チーム・アプリのキーとコストを一箇所で管理・制限・可視化したい
- MCPサーバが増え、エージェントごとに接続先と認可を持たせたくない

逆に1アプリ1モデルで完結するなら不要。ホップが増える分のレイテンシと運用コストに見合わない。

実際にOpenRouterとAgentRouterを触ってみたらよりイメージが掴めそう。
