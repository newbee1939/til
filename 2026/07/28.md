## BIND9について

https://www.isc.org/bind/

ISC が開発している DNS サーバーの実装。最も古く、最も広く使われている。「DNS サーバーを自前で建てる」＝だいたいこれ。現行の安定版は 9.20 系で、**偶数マイナーが安定版・奇数マイナーが開発版**。

### ISC とは

**Internet Systems Consortium**。1994 年設立の**非営利団体**で、企業ではない（[About](https://www.isc.org/about/)）。

- BIND 9 のほか、DHCP サーバーの **Kea** も開発している
- DNS の頂点にある**ルートサーバー（a〜m の 13 系統）のうち F-Root を自ら運用**している
- **anycast**（同じ IP のサーバーを世界中に置き、経路的に一番近い1台に届く仕組み）を DNS で最初に実用化した団体でもある
- 収入は、サポート契約の販売。「OSS を無料で維持するための費用を、必要とする企業が支払う」構造

### どこで使われている？

BIND は**独立した OSS の DNS 実装**であって、マネージド DNS の中身ではない。大手はそれぞれ自前実装を持っている。

つまり BIND を触るのは「**自分で DNS サーバーを持つ側**」。

### なぜ Route 53 で済ませないのか

インターネットに公開するドメインの権威 DNS だけなら Route 53 で十分で、BIND を選ぶ理由はほぼない。**分かれ目は「クラウドの外に自分のネットワークがあるか」**。

- **オンプレ・閉域網** … Route 53 の Private Hosted Zone は VPC に紐づく前提。そもそもインターネットに繋がっていない工場・閉域網では選択肢にならない
    - AWS 公式のハイブリッド構成図自体が「**オンプレ側に DNS リゾルバがいる**」前提で、Resolver outbound endpoint はそこへ転送するだけ（[Route 53 VPC Resolver](https://docs.aws.amazon.com/Route53/latest/DeveloperGuide/resolver.html)）。その「オンプレ側の DNS」の中身がまさに BIND
- **リゾルバが欲しい** … Route 53 は権威 DNS のサービス。ISP や大学が加入者向けフルリゾルバを提供する用途には使えない
- **Route 53 にない機能** … RPZ（特定ドメインの名前解決を遮断する DNS フィルタ）、`view` による細かい出し分けなど

なお **split DNS（社内は private IP、社外は public IP）は Route 53 でも Private Hosted Zone で普通にできる**。「split DNS だから自前が要る」わけではない。
