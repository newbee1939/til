## Cloudflare MCP Portal: Connect a private MCP server

https://developers.cloudflare.com/cloudflare-one/access-controls/ai-controls/mcp-portals/#connect-a-private-mcp-server

https://developers.cloudflare.com/changelog/post/2026-09-22-private-mcp-servers/

- MCP PortalからPrivateネットワーク経由でPrivateなMCP Serverと接続することが可能
- Cloudflare Gatewayを利用（MCP Serverをインターネットに公開しなくてよい）

前提

- MCP ServerのネットワークをCloudflareに繋いでおく（Cloudflare Tunnelなど）
- private hostname route か CIDR route を設定しておく

手順

1. 通常どおりMCP Serverを追加し、HTTP URLにprivateなURLを入れる
2. `Route traffic through Cloudflare Gateway` をONにする（必須）
3. `Save and connect server` → 必要ならOAuthを通す
4. ステータスが `Ready` になったらPortalに追加できる

## クライアント証明書とは？（認証方法）

- 繋ぎに来た側が「私は許可されたクライアントです」と名乗るための証明書
- 通常のTLSはサーバだけが証明書を出す。クライアントも出すのが mTLS（相互TLS）
- 流れ
  1. TLSハンドシェイク中にサーバが証明書を要求
  2. クライアントが証明書を提示し、対応する秘密鍵を持っていることを署名で示す
  3. サーバは、信頼するCAがその証明書に署名しているかを検証
- パスワードと違い、秘密鍵そのものはネットワークに流れない

## cfコマンドの始め方

https://blog.cloudflare.com/ja-jp/cloudflare-cf-cli-launch/

```shell
npm i -g cf
cf auth login
```

`cf auth login` がやること（https://developers.cloudflare.com/cf/get-started/）

- リンクとワンタイムコードを表示し、ブラウザでそのリンクを開く
- ブラウザ側で承認すると、`cf` がCloudflareアカウントを操作できるようになる

- Cloudflare API全体を扱える新しいCLI（Wranglerの後継）
- APIスキーマからコマンドを自動生成しているので、対応操作がWranglerより大幅に多い
- `cf init`（作成）/ `cf deploy`（デプロイ）/ `cf migrate`（Wranglerから移行）
