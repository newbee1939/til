## gcloud コマンド: リトライ回数

gcloud CLI の Cloud Storage 操作は、失敗すると指数バックオフ（待ち時間を倍々に伸ばしながら再試行）でリトライする。デフォルトの最大回数は 32 回。

プロパティ `storage/max_retries` で変えられる。

```sh
gcloud config set storage/max_retries 5
```

参考: [Cloud Storage: Retry strategy](https://docs.cloud.google.com/storage/docs/retry-strategy)

## Go: getter

Go の getter には `Get` を付けない。フィールド `owner` の getter は `Owner()`、setter は `SetOwner()`。

```go
owner := obj.Owner() // GetOwner() ではない
if owner != user {
    obj.SetOwner(user)
}
```

参考: [Effective Go: Getters](https://go.dev/doc/effective_go#Getters)

## Go: iota と Constant declarations

`iota` は `const ( ... )` の中で 0, 1, 2... と 1 行ごとに増える連番。式を省略した行は、直前の式をそのまま繰り返す扱いになる。この 2 つを組み合わせると連番定数を短く書ける。

```go
const (
    Sunday = iota // 0
    Monday        // 1（= iota を繰り返す）
    Tuesday       // 2
)
```

名前は略語ではない。ギリシャ文字の ι（イオタ）で、APL で連番を作る関数 `⍳` に由来する（C++ の `std::iota` も同じ由来）。Go の設計者自身が由来を説明した一次情報は見つからなかった。

参考:

- [cppreference: std::iota](https://en.cppreference.com/w/cpp/algorithm/iota)（Notes に APL 由来とある）
- [The Go Programming Language Specification: Iota](https://go.dev/ref/spec#Iota)
- [The Go Programming Language Specification: Constant declarations](https://go.dev/ref/spec#Constant_declarations)

## Google Cloud: scopes = ["cloud-platform"]

VM に付けるサービスアカウントのアクセススコープ（その VM から呼べる API の範囲）。`cloud-platform` は全 API を許可する。権限は IAM ロールで絞るのが推奨。

```hcl
service_account {
  email  = google_service_account.vm.email
  scopes = ["cloud-platform"]
}
```

スコープと IAM の両方で許可された操作だけが通る。スコープで細かく絞ると二重管理になるので、スコープは全開にして IAM 側で管理する。

参考: [Compute Engine: Service accounts](https://docs.cloud.google.com/compute/docs/access/service-accounts#accesscopesiam)
