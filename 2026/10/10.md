## プロセスとは

> 起動後に動作中のプログラムのこと

e.g. Linux上で動作するプログラム

## ⭐️Linux: カーネルの役割について

たとえば、プロセスがストレージデバイスに直接アクセス可能な場合、以下のような状況が起こりうる。

1. プロセス0がデータを書き込む場所を指定
2. プロセス1がデータを書き込む場所を指定
3. プロセス0がプロセス1が指定した場所にデータを書き込んでしまう

命令の実行順序を正しく制御しなければ危険...
また、本来はアクセスできてはいけないプログラムがデバイスにアクセスできてしまうのもよくない...

カーネルはハードウェアの助けを借りて、これらを防いでいる。（プロセスからデバイスに直接アクセスできないようにしている）

=> CPUに備わる、`モード`という機能を利用。

一般的に、CPUには以下の2つのモードがある。

- カーネルモード
- ユーザモード

プロセスがユーザモードで実行しているとき、「プロセスはユーザランド（ユーザ空間）で実行している」と言う。

カーネルモードの場合、特に制限はない。ユーザーモードの場合は特定の命令が実行できない。Linuxの場合は以下の通り。

- カーネルモード
    - カーネルのみがこのカーネルモードで動作
    - デバイスにアクセスできる
- ユーザモード
    - プロセスはユーザモードで動作
    - デバイスにアクセスできない

つまり、プロセスはカーネルを介して間接的にデバイスにアクセスする。

このようなデバイス制御に加えて、システム内のすべてのプロセスが共有するリソースを一元管理して、システム上で動作するプロセスに分配する。そのためにカーネルモードで動作するプログラムが、カーネル。

### 図1: 誰がどこにいるか（構造）

```
サーバー（機械そのもの。以下のハードウェアが入った箱）
│
├─ CPU ............ 命令を1つずつ実行する装置。プログラムの「置き場所」ではない
│    └─ モード ...... CPU（コア）が持つ「今どちらか」のスイッチ
│         ├─ ユーザモード:   デバイス操作などの命令は実行できない
│         └─ カーネルモード: 制限なし
│
├─ メモリ ......... 実行中のプログラムの置き場所。CPUはここから命令を読む
│    ├─ ユーザ空間:   プロセス0 / プロセス1 / ...（起動後に動作中のプログラム）
│    └─ カーネル空間: カーネル
│         ※ メモリのこの領域は、ユーザモードでは読み書きできない（守り1）
│
└─ ストレージデバイス ... データを保存する装置
          ※ デバイスを操作する命令は、ユーザモードでは実行できない（守り2）

OS（Linux）= カーネル + 基本的なプログラム群（シェル、ライブラリなど）
  ※ 厳密には「Linux」はカーネルの名前。カーネルはOSの中核部分
```

- カーネルもプロセスも「メモリに置かれたプログラム」。違いは、CPUがどちらのモードで実行するかだけ
- CPUは1つの瞬間に1つのコードしか実行できない。プロセスのコードか、カーネルのコードか
- 守り1と守り2は別のルールだが、門番はどちらもCPUのモード
    - 守り1（メモリ）: カーネルのコードを書き換えられると、チェック自体を消せてしまうので必要
    - 守り2（デバイス）: プロセスが勝手にストレージデバイスを操作できないようにする
    - ユーザモード中に破ろうとすると、CPUが実行を止めてカーネルに通報し、プロセスは通常 `SIGSEGV` で落とされる

### 図2: プロセスがファイルに書き込むとき（流れ）

```
CPUのモード      CPUが実行中のコード     起きていること
---------------------------------------------------------------------
ユーザモード     プロセス0のコード       普通の計算。デバイスには触れない
                      |
                      |  write() を呼ぶ = システムコール
                      v  （CPUの専用命令でモードが切り替わる。x86-64なら syscall 命令）
カーネルモード   カーネルのコード        依頼の中身と権限をチェックし、
                      |                  ストレージデバイスに書き込む
                      |  処理が終わる
                      v  （モードを戻す）
ユーザモード     プロセス0のコード       write() の次の行から続きを実行
```

- 上から下まで、動いているのはずっと「プロセス0」。CPUが読む先がカーネルのコードに一時的に移るだけ
- システムコール = ユーザモードからカーネルモードへ入るための、決められた唯一の正面玄関
    - 玄関が決まっているので、カーネルは必ずチェックを挟める（だから図冒頭の「書き込み場所の取り違え」を防げる）
- もう1つの入口が割り込み（デバイスやタイマーからの通知）。こちらはプロセスが頼んでいなくてもカーネルモードに入る
