## プロセスとは

> 起動後に動作中のプログラムのこと

e.g. Linux上で動作するプログラム

## ⭐️Linux: カーネルの役割について

たとえば、プロセスがストレージデバイスに直接アクセス可能な場合、以下のような状況が起こりうる。

1. プロセス0がデータを書き込む場所を指定
2. プロセス1がデータを書き込む場所を指定
3. プロセス0がプロセス1が指定した場所にデータを書き込んでしまう

命令の実行順序を正しく制御しなければ危険...
また、本来はアクセスできてはいけないプログラムがデバイスに直接アクセスできてしまうのもよくない...

カーネルはハードウェアの助けを借りて、これらを防いでいる。（プロセスからデバイスに直接アクセスできないようにしている）

=> CPUに備わる、`モード`という機能を利用。

一般的に、CPUには以下の2つのモードがある。

- カーネルモード
- ユーザモード

プロセスがユーザモードで実行しているとき、「プロセスは`ユーザランド（ユーザ空間）`で実行している」と言う。

カーネルモードの場合、特に制限はない。ユーザーモードの場合は特定の命令が実行できない。Linuxの場合は以下の通り。

- カーネルモード
    - カーネルのみがこのカーネルモードで動作
    - デバイスにアクセスできる
- ユーザモード
    - プロセスはユーザモードで動作
    - デバイスにアクセスできない

つまり、プロセスはカーネルを介して間接的にデバイスにアクセスする。

このようなデバイス制御に加えて、システム内のすべてのプロセスが共有するリソースを一元管理して、システム上で動作するプロセスに分配する。そのためにカーネルモードで動作するプログラムが、カーネル。

### 図: 誰がどこにいるか（構造）

```
サーバー（機械そのもの。以下のハードウェアが入った箱）
│
├─ CPU ............ 命令を1つずつ実行する装置。プログラムの「置き場所」ではない
│    └─ コア ........ CPUの中で実際に命令を実行する部分。1つのCPUに複数入っている
│         └─ モード ... コアごとに持つ「今どちらか」のスイッチ
│              ├─ ユーザモード:   デバイス操作などの命令は実行できない
│              └─ カーネルモード: 制限なし
│
├─ メモリ ......... 実行中のプログラムの置き場所。コアはここから命令を読む
│    ├─ ユーザ空間:   プロセス0 / プロセス1 / ...（起動後に動作中のプログラム）
│    └─ カーネル空間: カーネル
│         ※ メモリのこの領域は、ユーザモードでは読み書きできない（守り1）
│
└─ ストレージデバイス ... データを保存する装置
          ※ デバイスを操作する命令は、ユーザモードでは実行できない（守り2）

OS（Linux）= カーネル + 基本的なプログラム群（シェル、ライブラリなど）
  ※ 厳密には「Linux」はカーネルの名前。カーネルはOSの中核部分
```

- カーネルもプロセスも「メモリに置かれたプログラム」。違いは、コアがどちらのモードで実行するかだけ

### コアと「1つの瞬間に1つのコード」

- 1つのコアは、1つの瞬間に1つのコードしか実行できない。プロセスのコードか、カーネルのコードか
    - 「CPUは1つの瞬間に1つ」ではなく「コア1つにつき1つ」が正確
    - コアが4つあれば、同じ瞬間に4つのコードを実行できる（コアについては `2026/06/08.md`）
- モードもコアごと。コア0がカーネルモードでカーネルのコードを実行中に、コア1がユーザモードでプロセスを実行している、は普通に起こる

## ⭐️Linux: システムコールについて

プロセスがカーネルに処理を依頼するための方法。ユーザモードではできないこと（デバイスの操作など）を、カーネルに代わりにやってもらう。

```
[ユーザモード]    1. プロセス0が普通に計算している
                  2. プロセス0が write() を呼ぶ  <- システムコールの発行
       v             モードが上がり、実行位置が「カーネルが決めた入口」に飛ぶ
[カーネルモード]  3. カーネルのコードが依頼をチェック（書いてよいか、など）
                  4. カーネルのコードがストレージデバイスに書き込む
       v          5. 結果を用意して、モードを戻す
[ユーザモード]    6. プロセス0が戻り値を受け取り、続きを実行
```

- 1〜6まで、動いているのはずっと「プロセス0」。コアが読む先が、カーネルのコードに一時的に移るだけ
- 2で飛ぶ先をプロセスは選べない。だから3のチェックを飛ばして4には行けない
- `sar` の `%user` は1と6、`%system` は3〜5の時間の割合。`strace` は2を記録するツール（`2026/06/08.md`）
