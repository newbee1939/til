## reap: 刈り取り

実在する英単語。元は農業の「（作物を）刈り取る、収穫する」。

- reap the benefits: 成果を得る（比喩）
- IT では「終わったプロセスの後始末」。終了した子プロセスは親が `wait()` するまで「ゾンビ」として残る。`wait()` で回収することを reap と呼ぶ

参考: https://man7.org/linux/man-pages/man2/wait.2.html

## ⭐️php2shell（CVE-2026-109618 / 109619）

PHP 本体の脆弱性 2 件。ログイン不要の POST 1 つで、サーバー上で好きなコマンドを動かされる（RCE = Remote Code Execution）。CVSS 9.2（10 点満点、9.0 以上は最上位の Critical）。2026/10/21 に修正版が出た。

- 対象: Web リクエストを処理する PHP すべて（PHP-FPM / mod_php / php-cgi / FrankenPHP / LiteSpeed）
- 一番危ないのは mod_php。アプリのコードより前に攻撃が通ることが実証済み

### 2 つのバグ

| CVE | 一言で | 中身 |
| --- | --- | --- |
| 109618 | メモリ切れで後片付けが壊れる | わざとメモリを使い切らせる → PHP が処理を途中で打ち切る → 準備途中のデータを、後片付けが正しいものとして扱う |
| 109619 | 解放済みメモリを次のリクエストが使う | 途中で打ち切られると、解放済みメモリを指す変数が残る → 同じワーカーの次のリクエストがそれを使う（use-after-free = UAF） |

### 攻撃の流れ（109619 の Session Upload Progress 経路）

- ptr = メモリの番地を書いておく変数（ポインタ）。ここではリクエストをまたいで残るグローバル変数
- 係 = メモリの貸し出し係（アロケータ）。空き一覧を持つ
- ワーカー = リクエストを順番に処理する PHP のプロセス。何度も使い回される

```
① 1 回目: 攻撃者がアップロード（multipart）を送る
   ptr ──▶ 0x7000 [ 進捗データ ]

② 途中でエラー（メモリ切れなど。攻撃者が起こす）→ 処理を打ち切り   ← バグ
   メモリは解放されるが、ptr を消す処理は飛ばされる
   ptr ──▶ 0x7000 [ 空き ]            係の空き一覧: [0x7000]

③ 2 回目: 攻撃者のデータが 0x7000 に入る                          ← 攻撃者が突く
   PHP は届いたデータを置くため係からメモリを借りる → 係は空いている 0x7000 を貸す
   ptr ──▶ 0x7000 [ 攻撃者のデータ ]

④ 進捗処理が古い ptr を使う（use-after-free）                      ← バグ
   攻撃者のデータを正しい進捗データだと信じて動く → 処理の行き先を乗っ取られる

⑤ Web サーバーのユーザー（www-data など。root ではない）でコマンドが動く
   → .env の秘密を盗む / 裏口（Web シェル）を置く / クラウドへ広がる
```

③ の細かい手順（メモリ配置の仕込み方）は非公開。

### 対策

修正版に上げる。公式: "There are no complete mitigations, updating is the only safe choice."

- 修正版: 8.5.12 / 8.4.27 / 8.3.36 / 8.2.35。ディストリには事前にパッチが渡っているので、パッケージ更新でよい
- 8.1 以前: 公式リリースなし。ベンダーのバックポートを使うか、公式の 7.4 / 8.0 / 8.1 向けパッチでソースビルド
- 8.2 は 2026/12/31 でサポート終了。8.3 以降へ上げる計画も立てる

すぐ上げられないときの緩和（一部の経路を塞ぐだけで、安全にはならない）:

| 対象 | 設定 |
| --- | --- |
| 109618 | `memory_limit=-1` を `php_admin_value` で固定 |
| 109618 | `post_max_size` を小さく（8M、アップロードありなら 32M）。プロキシでもリクエストの大きさを制限 |
| 109619 | `session.upload_progress.enabled=0`（`php.ini` か FPM pool に書く。`ini_set()` / `.user.ini` は効かない） |
| 109619 | `fatal_error_backtraces=0`（8.5 のみ） |

- 設定を変えたら全ワーカーを再起動する
- メモリ制限は cgroup で。`RLIMIT_AS` / `RLIMIT_DATA` はメモリ切れを起こしてバグを招くので使わない
