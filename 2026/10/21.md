## reap: 刈り取り

実在する英単語。元は農業の「（作物を）刈り取る、収穫する」。

- reap the benefits: 成果を得る（比喩）
- IT では「終わったプロセスの後始末」。終了した子プロセスは親が `wait()` するまで「ゾンビ」として残る。`wait()` で回収することを reap と呼ぶ

参考: https://man7.org/linux/man-pages/man2/wait.2.html

## ⭐️php2shell（CVE-2026-109618 / 109619）

PHP 本体の脆弱性。ログイン不要で、外から 1 つの HTTP リクエストを送るだけでサーバー上でコマンドを実行される（RCE）と言われている。CVSS 9.2。

公式（php.net）が出しているのは「重大な脆弱性 2 件、CVSS 9.2、10/21 14:00 UTC に修正版」だけ。UAF や Session Upload Progress が原因という話はリーク・推測で、公式は未確認（2026/10/21 時点）。Cloudflare は攻撃の初期兆候を観測したと発表。

RCE（Remote Code Execution）= 遠隔からのコード実行。ネット越しに、他人のサーバーで好きな命令を動かせてしまうこと。サーバーを丸ごと乗っ取られるのとほぼ同じなので、脆弱性の中で最も深刻な部類。

CVSS（Common Vulnerability Scoring System）= 脆弱性の深刻さを 0.0〜10.0 で表す共通の物差し。FIRST という団体が定めている。9.2 は最上位の Critical（9.0〜10.0）。

| 0.1〜3.9 | 4.0〜6.9 | 7.0〜8.9 | 9.0〜10.0 |
| --- | --- | --- | --- |
| Low | Medium | High | Critical |

参考: https://www.first.org/cvss/v4.0/specification-document

### どういうバグか（推測）: use-after-free（UAF）

返したメモリを、うっかり使い続けてしまうバグ。UAF はバグの種類の名前（CWE-416）で、php2shell 固有の名前ではない。具体的な手口は未公開なので、以下は UAF の典型的な流れ。

ptr = ポインタ。メモリの番地（住所）を書いておく変数。
係 = アロケータ。メモリの貸し出し係で、「空き一覧」を持っている。

```
① PHP が係からメモリ 0x7000 を借りて、「次に呼ぶ関数 = A」と書く
   ptr ──▶ 0x7000 [ 関数 A の番地 ]          係の空き一覧: [ ]

② PHP が 0x7000 を返す（free）。でも ptr は 0x7000 のまま   ← 脆弱性その1
   ptr ──▶ 0x7000 [ 空き ]                   係の空き一覧: [0x7000]
   なぜ？ free は係の空き一覧に 0x7000 を書き戻すだけ。
         ptr（住所メモ）は自動では消えない（C ではふつうの動き）。
         本来は自分で ptr を消す。PHP はこれを忘れている

③ 攻撃者が送ったファイル名が 0x7000 に入る                  ← 攻撃者が突く
   ptr ──▶ 0x7000 [ system() の番地 ] ◀── ファイル名   係の空き一覧: [ ]
   なぜ？ PHP は届いたファイル名を置くため、係にメモリを借りる（ふつうの処理）。
         係は空き一覧の先頭 0x7000 を貸す。
         ファイル名の中身は攻撃者が自由に決められる

④ PHP が古い ptr を使う（use-after-free）                   ← 脆弱性その2
   ptr ──▶ 0x7000 [ system() の番地 ] ──▶ system() が動く
   なぜ？ PHP は 0x7000 に「関数の番地」があると信じて、そこへ飛ぶ。
         中身が入れ替わったことには気づけない

⑤ 攻撃者のコマンドが www-data（Web サーバー用のユーザー。root ではない）で動く
   → .env の秘密を盗む / 裏口（Web シェル）を置く / クラウドへ広がる
```

- system() = OS コマンドを実行する、PHP に元からある関数
- 入口は Session Upload Progress（アップロード進捗の記録、既定で有効）。POST に `PHP_SESSION_UPLOAD_PROGRESS` を付けるだけで、ファイル名をメモリに置く処理が動く。アプリより前に動くので、どのサイトにも届く

### 対策

- 修正版を当てる（10/21 14:00 UTC = 23:00 JST 予定）。パッケージの changelog に CVE 番号があるかで確認
- 修正が出るのはサポート中の 8.2 以降だけ。8.1 以前は公式の修正なし → 上げるか、ディストリのバックポートを待つ
- `session.upload_progress.enabled=0` は部分的な緩和にすぎない。PHP コア開発者は「パッチ以外に緩和策はない」と発言
