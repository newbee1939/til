## reap: 刈り取り

実在する英単語。元は農業の「（作物を）刈り取る、収穫する」。

- reap the benefits: 成果を得る（比喩）
- IT では「終わったプロセスの後始末」。終了した子プロセスは親が `wait()` するまで「ゾンビ」として残る。`wait()` で回収することを reap と呼ぶ

参考: https://man7.org/linux/man-pages/man2/wait.2.html

## ⭐️php2shell（CVE-2026-109618 / 109619）

PHP 本体の脆弱性。ログイン不要で、外から 1 つの HTTP リクエストを送るだけでサーバー上でコマンドを実行される（RCE）と言われている。CVSS 9.2。詳細は未公開で、以下はリーク情報ベース。

RCE（Remote Code Execution）= 遠隔からのコード実行。ネット越しに、他人のサーバーで好きな命令を動かせてしまうこと。サーバーを丸ごと乗っ取られるのとほぼ同じなので、脆弱性の中で最も深刻な部類。

CVSS（Common Vulnerability Scoring System）= 脆弱性の深刻さを 0.0〜10.0 で表す共通の物差し。FIRST という団体が定めている。9.2 は最上位の Critical（9.0〜10.0）。

| 0.1〜3.9 | 4.0〜6.9 | 7.0〜8.9 | 9.0〜10.0 |
| --- | --- | --- | --- |
| Low | Medium | High | Critical |

参考: https://www.first.org/cvss/v4.0/specification-document

### どういうバグか: use-after-free（UAF）

解放したメモリを、まだ使い続けてしまうバグ。

ptr = ポインタ（メモリの番地を覚えておく変数）。PHP は ptr の先に書かれた関数を呼ぶ。

```
① 確保して使う
   ptr ──▶ 0x7000 [ 関数 A のアドレス ] ──▶ 関数 A が動く（正常）

② 解放（free）。でも ptr は 0x7000 を指したまま
   ptr ──▶ 0x7000 [ 空き ]
                    ↑ アロケータ「0x7000 は空いた。次の確保に回そう」

③ 再利用。攻撃者のデータが入る
   ptr ──▶ 0x7000 [ 攻撃者が選んだアドレス ] ◀── 攻撃者のリクエスト
                    ↑ アロケータは ptr の存在を知らない。空きだから貸しただけ

④ 解放後に使う（use-after-free）
   ptr ──▶ 0x7000 [ 攻撃者が選んだアドレス ] ──▶ 攻撃者のコードが動く
```

### なぜ攻撃者のデータがメモリに入るのか

サーバーは、受け取ったリクエストを処理するために中身をメモリにコピーする。これは正常な動き。そしてリクエストの中身は攻撃者が自由に決められる。

```
攻撃者の POST
  filename="\x40\x12\x7f..."    ← 中身は自由に決められる
      │ PHP が処理のためメモリにコピー（正常）
      ▼
  0x7000 [ \x40\x12\x7f... ]    ← コピー先が解放済みの場所なら ③ が成立
```

- 送るのは関数そのものではなく、アドレスに見えるバイト列。PHP がそれを「関数のアドレス」として読んでしまう
- 飛び先は `system()`（OS コマンドを実行する関数）のように、PHP に元からある関数（一般的な手口）。その場所を知るためにアドレスをリークして ASLR（アドレスのランダム化）を破る

### 入口: Session Upload Progress

アップロードの進み具合をセッションに記録する機能。既定で有効。

- POST に `PHP_SESSION_UPLOAD_PROGRESS` を付けるだけで、ファイル名などをメモリにコピーする処理が動く。ここに UAF があると推測されている
- アプリのコードより前に動くので、アップロード機能が無いサイトにも届く

### 攻撃の流れ

```
攻撃者（ログイン不要）
  │ ① 細工した POST を送る
  ▼
PHP 本体（アプリより前）
  │ ② UAF で、解放済みメモリが攻撃者のデータに置き換わる
  │ ③ PHP がそれを関数のアドレスとして読み、飛ぶ
  ▼
www-data 権限でコマンド実行
  → .env の秘密を盗む / Web シェル設置 / IAM ロールでクラウドへ
```

### 対策

- 修正版を当てる（10/21 公開）。パッケージの changelog に CVE 番号があるかで確認
- `session.upload_progress.enabled=0` は応急処置。2 つ目のバグは別経路（multipart の解析処理）との説があり、これだけでは防げない
