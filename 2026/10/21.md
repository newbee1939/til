## reap: 刈り取り

実在する英単語。元は農業の「（作物を）刈り取る、収穫する」。

- reap the benefits: 成果を得る（比喩）
- IT では「終わったプロセスの後始末」。終了した子プロセスは親が `wait()` するまで「ゾンビ」として残る。`wait()` で回収することを reap と呼ぶ

参考: https://man7.org/linux/man-pages/man2/wait.2.html

## ⭐️php2shell（CVE-2026-109618 / 109619）

PHP 本体の脆弱性 2 件。ログイン不要で、細工した POST を送るだけでサーバー上で好きなコマンドを動かされる（RCE）。CVSS 9.2。10/21 に修正版が出た（公式発表あり）。

- RCE（Remote Code Execution）= 遠隔からのコード実行。サーバーを乗っ取られるのとほぼ同じ
- CVSS = 脆弱性の深刻さを 0.0〜10.0 で表す共通の物差し。9.0 以上は最上位の Critical

### 2 つのバグ

| CVE | 一言で | 中身 |
| --- | --- | --- |
| 109618 | メモリ切れで後片付けが壊れる | 攻撃者がわざとメモリを使い切らせる → PHP は処理を途中で打ち切る → 準備途中の壊れたデータを、後片付け処理が正しいものとして扱う |
| 109619 | 解放済みメモリを次のリクエストが使う | 途中で打ち切られると、グローバル変数が解放済みメモリを指したまま残る → 同じプロセスの次のリクエストがそれを使う（use-after-free） |

use-after-free（UAF）= 返したメモリを使い続けてしまうバグの種類の名前（CWE-416）。

### 攻撃の流れ（109619 の Session Upload Progress 経路）

- ptr = ポインタ。メモリの番地を書いておく変数。ここではリクエストをまたいで残るグローバル変数
- 係 = アロケータ。メモリの貸し出し係で、空き一覧を持つ
- ワーカー = リクエストを順番に処理する PHP のプロセス。1 つのプロセスが何度も使い回される

```
① 1 回目のリクエスト: 攻撃者がアップロード（multipart）を送る
   PHP がメモリ 0x7000 にアップロード進捗のデータを置き、ptr に番地を書く
   ptr ──▶ 0x7000 [ 進捗データ ]

② 途中でメモリ切れ（攻撃者がわざと起こす）→ PHP は処理を打ち切る    ← バグ
   リクエストのメモリは解放される。でも ptr を消す処理は飛ばされる
   ptr ──▶ 0x7000 [ 空き ]              係の空き一覧: [0x7000]
   なぜ残る？ 解放は係の空き一覧に番地を戻すだけ。ptr は自分で消す必要がある

③ 2 回目のリクエスト: 攻撃者のデータが 0x7000 に入る                ← 攻撃者が突く
   ptr ──▶ 0x7000 [ 攻撃者のデータ ]    係の空き一覧: [ ]
   なぜ入る？ PHP は届いたデータを置くため係からメモリを借りる（ふつうの処理）
             係は空き一覧の 0x7000 を貸す。データの中身は攻撃者が決められる

④ PHP の進捗処理が古い ptr を使う（use-after-free）                ← バグ
   ptr ──▶ 0x7000 [ 攻撃者のデータ ] → 正しい進捗データだと信じて動く
   メモリの配置をうまく仕込むと、PHP の処理の行き先を乗っ取れる

⑤ 攻撃者のコマンドが Web サーバーのユーザー（www-data など。root ではない）で動く
   → .env の秘密を盗む / 裏口（Web シェル）を置く / クラウドへ広がる
```

- アプリのコードより前に起きるので、WordPress でも Laravel でも関係なく届く
- Web リクエストを処理する PHP はすべて対象（PHP-FPM、mod_php、php-cgi、FrankenPHP、LiteSpeed）。一番危ないのは mod_php で、攻撃が実証済み

### 対策

修正版に上げるのが唯一の完全な対策（公式: "updating is the only safe choice"）。

- 修正版: 8.5.12 / 8.4.27 / 8.3.36 / 8.2.35。ディストリには事前にパッチが渡っているので、パッケージ更新でよい
- 8.1 以前は公式リリースなし。ディストリ / LTS ベンダーのバックポートを使うか、7.4〜8.1 向けパッチを当ててソースからビルド

すぐ上げられないときの緩和（部分的。これで安全にはならない）:

| 対象 | 設定 | 注意 |
| --- | --- | --- |
| 109618 | `memory_limit=-1`（`php_admin_value` で固定） | メモリ切れ自体は他の原因でも起きうる |
| 109618 | `post_max_size` を小さく（8M、アップロードありなら 32M）＋プロキシでも制限 | |
| 109619 | `session.upload_progress.enabled=0` | `php.ini` か FPM pool に書く。`ini_set()` / `.user.ini` は不可 |
| 109619 | `fatal_error_backtraces=0`（8.5 のみ） | |

- 設定を変えたらワーカーを全部再起動する
- cgroup でメモリを制限するのは可。`RLIMIT_AS` / `RLIMIT_DATA` は逆にバグを起こすので使わない
