## ⭐️php2shell（CVE-2026-109618 / 109619）

PHP 本体の脆弱性。ログイン不要で、外から 1 つの HTTP リクエストを送るだけでサーバー上でコマンドを実行される（RCE）と言われている。CVSS 9.2。

公式（php.net）が出しているのは「重大な脆弱性 2 件、CVSS 9.2、10/21 14:00 UTC に修正版」だけ。UAF や Session Upload Progress が原因という話はリーク・推測で、公式は未確認（2026/10/21 時点）。Cloudflare は攻撃の初期兆候を観測したと発表。

RCE（Remote Code Execution）= 遠隔からのコード実行。ネット越しに、他人のサーバーで好きな命令を動かせてしまうこと。サーバーを丸ごと乗っ取られるのとほぼ同じなので、脆弱性の中で最も深刻な部類。

CVSS（Common Vulnerability Scoring System）= 脆弱性の深刻さを 0.0〜10.0 で表す共通の物差し。FIRST という団体が定めている。9.2 は最上位の Critical（9.0〜10.0）。

| 0.1〜3.9 | 4.0〜6.9 | 7.0〜8.9 | 9.0〜10.0 |
| --- | --- | --- | --- |
| Low | Medium | High | Critical |

参考: https://www.first.org/cvss/v4.0/specification-document

### どういうバグか（推測）: use-after-free（UAF）

解放したメモリを、まだ使い続けてしまうバグ。UAF はバグの種類の名前（CWE-416）で、php2shell 固有の名前ではない。

ptr = ポインタ（メモリの番地を覚えておく変数）。PHP は ptr の先に書かれた関数を呼ぶ。

```
① 確保して使う
   ptr ──▶ 0x7000 [ 関数 A のアドレス ] ──▶ 関数 A が動く（正常）

② 解放（free）。でも ptr は 0x7000 を指したまま
   ptr ──▶ 0x7000 [ 空き ]
                    ↑ アロケータ「0x7000 は空いた。次の確保に回そう」

③ 再利用。攻撃者のデータが入る
   ptr ──▶ 0x7000 [ 攻撃者が選んだアドレス ] ◀── 攻撃者のリクエスト
                    ↑ アロケータは ptr の存在を知らない。空きだから貸しただけ

④ 解放後に使う（use-after-free）
   ptr ──▶ 0x7000 [ 攻撃者が選んだアドレス ] ──▶ 攻撃者のコードが動く
```

### 攻撃の流れ（例）

ポイントは 1 つ。ファイル名は攻撃者が好きに書ける文字列で、PHP はそれを普通にメモリに置く。UAF があると、PHP はその文字列を「次に呼ぶ関数の番地」と取り違えて読む。

```
① 攻撃者: ファイル名に「system() の番地」を書いて POST（ログイン不要）
          ※ system() = OS コマンドを実行する、PHP に元からある関数

② PHP:    ファイル名をメモリに置く（普通の処理）
          置き場所が、たまたま解放済みの 0x7000

③ PHP:    古い ptr で 0x7000 を読む
          「次に呼ぶ関数はここか」→ system() を呼んでしまう

④ 結果:   攻撃者のコマンドが www-data 権限で動く
          → .env の秘密を盗む / Web シェル設置 / IAM ロールでクラウドへ
```

- ファイル名をメモリに置く処理は Session Upload Progress（アップロード進捗の記録、既定で有効）。POST に `PHP_SESSION_UPLOAD_PROGRESS` を付けるだけで動く
- アプリのコードより前に動くので、アップロード機能が無いサイトにも届く
- www-data = Debian / Ubuntu で Web サーバーや PHP を動かす一般ユーザー。root ではない。ただし Web サーバーが読めるもの（ソース、`.env`）は全部読める。別の脆弱性と組み合わせて root を奪われることもある（権限昇格）

### 対策

- 修正版を当てる（10/21 14:00 UTC = 23:00 JST 予定）。パッケージの changelog に CVE 番号があるかで確認
- 修正が出るのはサポート中の 8.2 以降だけ。8.1 以前は公式の修正なし → 上げるか、ディストリのバックポートを待つ
- `session.upload_progress.enabled=0` は部分的な緩和にすぎない。PHP コア開発者は「パッチ以外に緩和策はない」と発言
