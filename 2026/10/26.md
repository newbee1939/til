## ⭐️GitHub Actions: JIT runner（Just-In-Time）

1 ジョブだけ動いて消える self-hosted runner。

1 ジョブ = ワークフローの `jobs:` の 1 つが 1 回実行されること。matrix なら組み合わせごと、Re-run も別ジョブ扱い。

### トークンとの関係

「秘密鍵 → JWT → installation access token」の先で、`runner の登録方法`が 2 つに分かれる。違いは「誰が、いつ登録するか」。

管理役 = GitHub App の鍵を持ち、API を叩いて runner を用意する側（ARC のコントローラや自作スクリプト）。runner 本体とは別物。

```
registration token（登録は runner がやる）
  管理役: .../registration-token  → registration token をもらう（1 時間有効）
  runner: config.sh --token トークン → runner が GitHub に「登録して」と頼む
  runner: run.sh                  → ジョブを待つ。終わっても次のジョブを待ち続ける

JIT config（登録は管理役がやる）
  管理役: .../generate-jitconfig  → この時点で GitHub 側に登録が済み、認証情報が返る
  runner: run.sh --jitconfig 認証情報 → 登録の手順なしで即起動。1 ジョブ終えたら登録解除
```

### 認証情報の流れ（registration token の場合）

```
管理役
  1. 秘密鍵で JWT に署名（RS256、有効期限は最大 10 分）
  2. POST /app/installations/{id}/access_tokens（Authorization: Bearer JWT）
     → installation access token（1 時間有効）
  3. POST /orgs/{org}/actions/runners/registration-token（Bearer installation token）
     → registration token（1 時間有効）
  4. registration token を runner に渡す ← GitHub は関与しない。渡し方は自分で決める
runner
  5. config.sh --token → 登録時に RSA 鍵ペアを作り、公開鍵を GitHub に送る
     → .runner（設定）と .credentials（OAuth 設定）を保存。registration token はここで用済み
  6. run.sh → 手元の秘密鍵で GitHub に認証し、ジョブを待つ
```

4 の渡し方の例: VM の起動スクリプト（user-data）、環境変数、Kubernetes Secret。秘密鍵と installation token は管理役から出さない。

- registration token: 「登録してよい」という短命のトークン文字列（`token` と `expires_at` が返る）。登録作業は runner 側に残る
- JIT config: 登録済みの runner の認証情報そのもの（base64）。runner はファイルに書き出して起動するだけ

### 手動登録との関係

手動登録（Settings → Actions → Runners → New self-hosted runner）も同じ registration token。違いはトークンを出すのが App ではなく、画面の人間なだけ。

### 比較

| | registration token | JIT config |
| --- | --- | --- |
| 出し方 | 画面 or API | API のみ |
| 登録するのは | runner（`config.sh`） | 管理役（API を叩いた時点） |
| 常駐 / 使い捨て | どちらも可（`--ephemeral`） | 使い捨てのみ |
| ラベル・runner group | runner 側で指定 | 発行時に API で指定 |
| メリット | 手軽。手動でも始められる | 登録手順なしで即起動。runner に登録の権限を渡さない |
| デメリット | 常駐だと前のジョブの痕跡が残り、乗っ取られた runner が次のジョブも受ける | 管理役（ARC や自作）が要る |

使い捨て共通の注意（公式）: ログは外部に転送して残す。コンテナだと起動のたびに runner の自動更新が走るので `--disableupdate` でイメージ側で更新する（30 日以内に更新は必要）。

### 外部から登録する意味

```
GitHub ──ジョブ来た──▶ 管理役（鍵あり）
                         │ JIT config を発行
                         ▼
                      runner（鍵なし）→ 1 ジョブ実行 → 消える
```

- runner に GitHub App の鍵を置かない。ジョブを乗っ取られても鍵は漏れない
- 毎回まっさらな環境。前のジョブの秘密情報が残らない
- ジョブが来た分だけ作れる（オートスケール）

これを Kubernetes でやる GitHub 公式の仕組みが ARC（Actions Runner Controller）。
