## Claude Managed Agents: ワークフロー実行

エージェントが書いたプログラム（ワークフロー）で、多数のエージェントを走らせて結果をまとめる仕組み。その1回分の実行が workflow run。1つの会話に収まらない大きな仕事向け。

```
ワークフロー実行
└─ フェーズ（名前付きの段階）
     └─ エージェントスレッド（並列実行できる）
```

- 開始できるのはエージェントだけ。こちらからは開始も終了もできない
- 進捗はセッションのイベントストリームで追う（`workflow_run.created` → `status_ended`）

参考: https://platform.claude.com/docs/en/managed-agents/workflow-runs

実際に触ってみないとイメージ掴めないかも。

## DNSレコード: shadowed records

サブドメインを NS レコードで委任したとき、その名前以下に残っているレコードのこと。権威が委任先に移るので応答されない。エラーにならないので気づきにくい。

```
sub.example.com      NS  ns1.other.net   ← 委任
api.sub.example.com  A   192.0.2.1       ← shadowed（応答されない）
```

参考: https://developers.cloudflare.com/dns/manage-dns-records/reference/shadowed-records/

## cloudflare_zero_trust_access_application

Cloudflare Access のアプリケーション（Access で保護する対象）を管理するリソース。

- `type`: アプリの種類（`self_hosted`、`saas` など）
- `policies`: 誰を通すかのリスト。`precedence` の小さい順に適用
- `account_id` と `zone_id` はどちらか一方だけ指定

参考: https://registry.terraform.io/providers/cloudflare/cloudflare/latest/docs/resources/zero_trust_access_application

## SLSA / Sigstore / Binary Authorization

ソフトウェアサプライチェーン（コードがビルドされてデプロイされるまでの経路）を守る3つ。役割が違う。

| 名前 | 何か | 役割 |
| --- | --- | --- |
| SLSA | 基準 | ビルドの信頼度をレベル（L0〜L3）で表す |
| Sigstore | ツール群 | 成果物に署名して検証する。長期の鍵を管理しなくてよい |
| Binary Authorization | Google Cloud のサービス | 条件を満たすイメージだけデプロイさせる |

参考:

- https://slsa.dev/spec/v1.0/levels
- https://docs.sigstore.dev/about/overview/
- https://docs.cloud.google.com/binary-authorization/docs/overview
