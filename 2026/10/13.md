## SRE: 飽和度

ゴールデンシグナルの一つ。

> How "full" your service is.

- 最も制約のあるリソース（メモリ、I/O など）がどれだけ埋まっているか
- 100% になる前に性能が落ち始めるので、目標値は手前に置く
- 「あと4時間でディスクが埋まる」のような予測も含む

参考: https://sre.google/sre-book/monitoring-distributed-systems/

## Terraform: try文

引数を順に評価して、エラーにならなかった最初の値を返す関数。

```hcl
try(local.foo.bar, "fallback")   # bar があればその値、なければ "fallback"
```

- 捕まえられるのは実行時までわからないエラーだけ（属性がない、など）
- 使いすぎると読みにくくなる。公式は、データの形を整える locals の中だけで使うことを勧めている

参考: https://developer.hashicorp.com/terraform/language/functions/try

## terraform test: 概要

Terraform の設定をテストする公式の仕組み（v1.6.0 から）。`.tftest.hcl` に書く。

```hcl
run "check_name" {
  command = plan

  assert {
    condition     = aws_s3_bucket.bucket.bucket == "demo-bucket"
    error_message = "unexpected bucket name"
  }
}
```

- `run` が1つのテスト。`assert` の `condition` が false なら失敗
- デフォルトは `command = apply` で実際にリソースを作る（終わると自動で destroy）。`plan` なら作らない

参考: https://developer.hashicorp.com/terraform/language/tests
