## reap: 刈り取り

実在する英単語。元は農業の「（作物を）刈り取る、収穫する」。

- reap the benefits: 成果を得る（比喩）
- IT では「終わったプロセスの後始末」。終了した子プロセスは親が `wait()` するまで「ゾンビ」として残る。`wait()` で回収することを reap と呼ぶ

参考: https://man7.org/linux/man-pages/man2/wait.2.html

## ⭐️php2shell（CVE-2026-109618 / 109619）

PHP 本体の脆弱性 2 件。ログイン不要のリクエストを送るだけで、サーバー上で任意のコマンドを動かされる。

- RCE（Remote Code Execution）: 外部から好きなコードを実行されること。乗っ取りとほぼ同義
- CVSS: 脆弱性の深刻度を 0〜10 で表す共通の点数。今回は 9.2（9.0 以上は最上位の Critical）

### どんな脆弱性か

わざと処理を途中で打ち切らせ、壊れた状態を正しいものとして使わせる。

```
109618（1 リクエスト）
  巨大な POST → メモリ切れで打ち切り → 後片付けが準備途中のデータを使う → 乗っ取り

109619（2 リクエスト。ワーカーは使い回される）
  1 回目: わざとエラー → メモリは解放、ptr（番地を指す変数）だけ残る
  2 回目: 同じ場所に攻撃者のデータ → 古い ptr が使う（use-after-free）→ 乗っ取り
```

### 状況

- 対象: Web で動く PHP すべて（FPM / mod_php など）。5.x〜8.x の修正版未満
- 10/21 修正版公開。修正前から攻撃が始まり、10/22 には Web シェルを置く攻撃も観測。国内 50 以上の組織がサービスを一時停止

### 対策

- 修正版 8.5.12 / 8.4.27 / 8.3.36 / 8.2.35 に上げる。公式いわく完全な緩和策はない
- 8.1 以前は公式リリースなし。ベンダーのバックポートか、サポート中の版へ移行
- つなぎ: `session.upload_progress.enabled=0`（109619）、`memory_limit=-1`（109618）、プロキシで multipart を制限（両方）

参考:
- https://www.php.net/archive/2026.php#2026-10-21-5
- https://blog.flatt.tech/entry/php2shell
- https://ellio.tech/en/blog/php2shell-what-we-observed-and-what-to-do/

## ⭐️Session Upload Progress

ファイルのアップロード中に、PHP が進捗を `$_SESSION` に書き込む機能。別のリクエストで読めばプログレスバーが作れる。

- multipart（`multipart/form-data`）: 1 回の POST の本文を区切り文字で分け、テキストとファイルを一緒に送る形式。アップロードのフォームで使う

```
① ブラウザ: ファイルと一緒に「受付番号 123」を送る（multipart の POST）

② PHP 本体: 受け取りながら、セッションに進捗をメモしていく
     「123 番: 100MB 中 40MB 受信済み」

③ ブラウザ: 別のリクエストで「123 番どう？」と聞く → 40% と表示
```

- 受付番号は `PHP_SESSION_UPLOAD_PROGRESS` という名前の隠しフィールドで送る（ファイルより前に置く）
- ② はアプリのコードが動く前に PHP 本体がやる

- デフォルトで有効（`session.upload_progress.enabled=1`）。アプリが使っていなくても PHP 本体が勝手に動く
- php2shell の 109619 の経路。使わないなら `session.upload_progress.enabled=0`

参考: https://www.php.net/manual/en/session.upload-progress.php

## Akamai の本番 / ステージングの IP を引く

```sh
dig +short example.com CNAME
# → example.com-v1.edgekey.net.

dig +short example.com-v1.edgekey.net          # 本番
dig +short example.com-v1.edgekey-staging.net  # ステージング
```

- `+short`: dig の出力から答え（ANSWER の値）だけを表示する。ヘッダーや統計は省く
- ステージングは `edgekey.net` を `edgekey-staging.net` に変えるだけ（Akamai 公式の方法）
- ステージングの IP は変わるので、使うたびに引き直す（Akamai 公式の注意）
- hosts に IP と本来のドメインを書いて確認。レスポンスに `X-Akamai-Staging` ヘッダーがあればステージング

参考: https://techdocs.akamai.com/api-acceleration/docs/test-stage

## ⭐️Use After Free

返したはずのメモリを、まだ自分のものだと思って使うバグ（UAF）。

メモリをロッカーにたとえる。登場するのは PHP の中のプログラム 2 つ（人ではない）。

- 進捗係（p）: アップロードの進捗を管理する PHP 内部の処理
- 受信係（q）: 届いたリクエストのデータを置く PHP 内部の処理
- 攻撃者: 外からリクエストを送るだけ。メモリには直接触れない

```
① 進捗係が 7 番を借り、「7 番」とメモする    7 番: [進捗データ]
② 進捗係が 7 番を返す。メモは消し忘れる      7 番: [空き]
③ 受信係が空いた 7 番を借り、届いたデータを入れる
                                             7 番: [攻撃者が送ったデータ]
④ 進捗係がメモを見て 7 番を開け、中身を進捗データだと思って使う
```

なぜ危ないか: 同じ中身でも、どの係が読むかで扱いが変わる。

進捗係のメモは決まった書式になっている。攻撃者はその書式に合わせてデータを作る。

```
進捗係のメモの書式          攻撃者が送ったデータ
  1 行目: 受信済みバイト数    AAAA        ← 何でもいい（埋め草）
  2 行目: 次に呼ぶ処理の場所  0x7f123456  ← 狙いはここ
```

- 受信係にとってはただの文字列なので、置くだけで無害
- 進捗係は 2 行目を「次に呼ぶ処理の場所」と信じて、そこへジャンプする
- 0x7f123456 にコマンドを実行する処理を置いておけば（または既存の関数を指せば）、好きなコマンドが動く = 乗っ取り
- 実際は防御（番地のランダム化など）を回避する手順も要る。php2shell の具体的な手順は非公開

- 攻撃者は本来「データ」しか送れない。進捗係に読ませることで「どこを実行するか」まで決められる（RCE）
- C / C++ で起きる。Rust や GC のある言語は言語の仕組みで防ぐ

参考: https://cwe.mitre.org/data/definitions/416.html
