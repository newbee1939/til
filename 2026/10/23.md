## reap: 刈り取り

実在する英単語。元は農業の「（作物を）刈り取る、収穫する」。

- reap the benefits: 成果を得る（比喩）
- IT では「終わったプロセスの後始末」。終了した子プロセスは親が `wait()` するまで「ゾンビ」として残る。`wait()` で回収することを reap と呼ぶ

参考: https://man7.org/linux/man-pages/man2/wait.2.html

## SARIF

静的解析の結果を書く共通 JSON 形式。「どのファイルの何行目に、どんな問題があるか」の一覧。

- GitHub に送ると Security タブ（Code scanning）にアラートとして出る
- 送るには `security_events: write` 権限のトークンが要る

参考: https://docs.github.com/en/code-security/code-scanning/integrating-with-code-scanning/sarif-support-for-code-scanning

## Akamai WAF 3つの機能の違い

- Core detections (コア検知)
  - 概要: SQLインジェクションやXSSなど、一般的なWebアプリケーション攻撃を防御するベースとなるルール群です。
  - 特徴: OWASP Top 10などの既知の脅威に対して継続的な保護を提供します。

- Rapid rules (ラピッドルール)
  - 概要: 新たに公表された深刻な脆弱性(ゼロデイ攻撃など)に対する緊急の保護ルールです。
  - 特徴: Akamaiの脅威対策チームが迅速に作成・配信し、システムにパッチを適用するまでの応急処置として機能します。

- Penalty box (ペナルティボックス)
  - 概要: 悪意のあるクライアントを特定し、一時的に通信を隔離する機能です。
  - 特徴: 短期間にWAFルールに繰り返し違反した攻撃者を検知し、一定期間自動的に通信を遮断します。

## ⭐️php2shellの件で改めて思ったこと

- 海外遮断はかなり有効（収益毀損はあるが...）
- 定期的なバージョンアップはやっぱり大事
- DBの権限も最小にしておく
    - クライアントごとにDBユーザー・パスワードは分ける
    - 権限もそれぞれのクライアントに合わせて最適化
        - 最小権限、アクセス可能なDBも最小化
- 管理しているシステムのバージョンをすぐに把握できる状態にしておく
- すぐにメンテナンス状態にできるようにしておく

当たり前のことを当たり前にコツコツするのは大変だけど、こういうときに楽をできる...

## ⭐️サービスアカウントがどうしても大きい権限を持つ必要がある場合

- なるべく付与対象を最小にする
    - e.g. 特定のサービスアカウントキーのみ対象にする
- 時間を絞って付与する（一時権限にする）
