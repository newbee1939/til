## Shannon: login flow

https://github.com/KeygraphHQ/shannon/blob/main/docs/configuration.md#writing-login-flow

> When typing into a field, reference the field by its exact label or placeholder.
>
> 訳: 入力欄に入力するときは、その欄の正確なラベルかプレースホルダーで指定する。

- Shannon: Web アプリ / API 向けの自律型 AI ペンテスター。実際に攻撃が成功したものだけを報告する
- `login_flow:` に、ログイン手順を自然言語のステップで並べて書く（シークレットウィンドウで人間が操作する手順そのまま）
- `$username` / `$password` / `$totp` などのプレースホルダーは、実行時に設定ファイルの認証情報で置き換えられる
- ログイン成功の判定は `success_condition`（例: URL に `/dashboard` を含む）
- `--validate-auth` でログインだけ試せる

## PostgreSQL の PUBLIC と public

https://www.postgresql.org/docs/current/ddl-priv.html

https://www.postgresql.org/docs/current/ddl-schemas.html

> The special “role” name PUBLIC can be used to grant a privilege to every role on the system.
>
> 訳: 特別な「ロール」名 PUBLIC を使うと、システム上のすべてのロールに権限を付与できる。

- 同じ名前で 2 つの意味がある
  - `PUBLIC` ロール: 全ユーザーを表す特別なロール。`GRANT ... TO PUBLIC` で全員に権限を渡せる
  - `public` スキーマ: どのデータベースにも最初からあるスキーマ。スキーマ名を省略して `CREATE TABLE` するとここに入る
- PostgreSQL 14 以前は「全員（PUBLIC）が public スキーマにテーブルを作れる」のがデフォルトだった。15 以降はできない
- 14 以前から上げた DB は手で `REVOKE CREATE ON SCHEMA public FROM PUBLIC;` する

## 決定論的シミュレーションテスト

> 最近面白いと感じている仕組みがあります。カオスエンジニアリングとプロパティベースドテストの考え方を、決定論的シミュレーションの上で組み合わせたテストの仕組みです。分散システムの正確性・信頼性・可用性を、障害やタイミングのずれを含む膨大なパターンで自動的に検証し、見つかった不具合は再現できる形で返してくれます。

- カオスエンジニアリング: 本番に近い環境へわざと障害（ネットワーク断・プロセス停止など）を入れて、システムが耐えるか確かめる
- プロパティベースドテスト: 「常に成り立つべき性質」を書き、入力はランダムに大量生成して検証する
- 決定論的シミュレーション: 時刻・スレッドの実行順・ネットワークなどを全部シミュレーター側で制御する。同じシードなら同じ実行になるので、バグを何度でも再現できる
- 製品の例: Antithesis

## Cloud Run で OpenTelemetry Collector をサイドカーとして動かす

https://zenn.dev/google_cloud_jp/articles/20230516-cloud-run-otel

https://cloud.google.com/run/docs/tutorials/custom-metrics-opentelemetry-sidecar

- 1 つのサービスにアプリと Collector の 2 コンテナを置く
- アプリは `localhost:4317` に OTLP で送るだけ。外部への送信や認証は Collector が担当する
- `run.googleapis.com/container-dependencies` で、Collector が起動してからアプリを起動させる
- 送り先は Managed Service for Prometheus。サービスアカウントに Monitoring Metric Writer ロールが必要

## RouteDNS

https://github.com/folbricht/routedns

> RouteDNS is a composable DNS stub resolver, proxy and router written in Go.
>
> 訳: RouteDNS は、部品を組み合わせて使える Go 製の DNS スタブリゾルバ・プロキシ・ルーター。

- 手元で DNS の問い合わせを受けて、条件に応じて上流のリゾルバへ振り分ける
- 振り分けの条件: ドメイン名（正規表現）、レコードの種類、送信元 IP など。上から順に見て、最初に一致したルールを使う
- 上流との通信は DNS（UDP / TCP）、DoT、DoH、DoQ などに対応
- ブロックリスト、キャッシュ、上流が落ちたときの切り替えもできる
- 設定は TOML。`routedns config.toml` で起動、`--check` で設定だけ検証
