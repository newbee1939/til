## ⭐️sping

https://github.com/LambdaBytes/sping

https://kawarimidoll.com/posts/202610201/

> Terminal-native, real-time connectivity monitor that doesn't just measure packets
>
> 訳: パケットを測るだけではない、ターミナルで動くリアルタイムの疎通モニター

- Rust 製の ping 代替 TUI
- ping との違い: 対象に加えてデフォルトゲートウェイと外部（既定 1.1.1.1）も同時に叩き、どこで切れているかを推定する
  - 例: 「ゲートウェイに届かない → LAN 側の問題」
- ICMP が塞がれた環境では `--tcp 443` で TCP 接続で測れる
- `sping 8.8.8.8 -c 5`

## WoT

https://www.keyence.co.jp/ss/general/iot-glossary/wot.jsp

https://www.w3.org/TR/wot-architecture11/

> The goal of the WoT is to preserve and complement existing IoT standards and solutions.
>
> 訳: WoT の目的は、既存の IoT 標準やソリューションを置き換えずに補うことである。

- Web of Things: W3C が進める、Web 技術（HTTP / JSON など）で IoT 機器を扱う仕組み
- 中心は Thing Description（TD）: 機器の情報と操作方法（読める値・実行できる操作・通信方式）を JSON で書いたもの
- メーカーやプロトコルが違う機器でも、TD を読めば同じやり方で操作できる

## Claude Vaults: の優先度の話

https://platform.claude.com/docs/en/managed-agents/vaults

> When multiple vaults contain a matching credential, the first vault with a match wins.
>
> 訳: 複数の Vault に一致する認証情報がある場合、最初に一致した Vault が使われる。

- セッション作成時に `vault_ids` で複数の Vault を渡せる
- MCP の認証情報は `mcp_server_url` で一致を判定する
- 同じ Vault 内では URL の重複は 409 エラー。Vault をまたげば重複できるので、この優先ルールがある
- 一致がなければ認証なしで接続し、認証必須のサーバーならエラー

## Jev と LLM の違い

Jev: TypeSafe AI が出した「System One モデル」。プロンプトを受け取り、文章を生成せずに選択肢ごとの確率を返す。

- 出力の違い
  - LLM: 「まずはサポート部門が妥当です…」と文章で答える
  - Jev: `A:1%, B:58%, C:41%, D:0%` と確率で答える
- プログラムで扱いやすい。確信度が分かるので「70% 以上なら自動、未満なら人間」と線を引ける
- 速くて安い理由
  - LLM の推論は Prefill（プロンプトを並列に処理して KV Cache を作る）と Decode（1 トークンずつ生成）の 2 段階
  - コストの大半は Decode。トークンごとに全語彙の logit を計算し、メモリ転送がボトルネックになる
  - Jev は Prefill の最後の状態から、選択肢（A〜D）の logit だけ計算して確率にする。Decode を丸ごと省ける
- 向いているのは判断・分類系のワークロード。文章が要る用途は引き続き LLM
