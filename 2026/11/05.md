## ⭐️PBT

Property-Based Testing。入力の例ではなく「どんな入力でも成り立つルール」を書くテスト。入力はツールが何百通りも自動で作る。

```python
# 例ベース: 自分で選んだ 1 ケースだけ確認
assert sort([3, 1, 2]) == [1, 2, 3]

# PBT: どんなリストでも「ソート後は小さい順」が成り立つか確認
@given(st.lists(st.integers()))
def test_sort(xs):
    ys = sort(xs)
    assert all(a <= b for a, b in zip(ys, ys[1:]))
```

例ベースだと、自分が思いつかない入力（空リスト、負数、重複）は試されない。PBT はそこを自動で突く。

## ⭐️Mutation Testing

テストの質をテストする手法。コードをわざと 1 か所壊して、テストが落ちるか確かめる。

```python
if age >= 18:   # 元のコード
if age > 18:    # わざと壊したコード
```

テストが落ちなければ、`age == 18` を誰も確認していないとわかる。カバレッジ 100% でも「実行しただけで結果を確かめていない」テストはこれで見つかる。

## ⭐️形式手法

設計を数式で書き、ツールで「ありうる全パターン」を調べて、ルールが破れないことを確かめる手法。

- テスト: 試したケースだけ確認できる
- 形式手法: 全パターンを確認できる。破れるなら、破れる手順を具体的に出してくれる

並行処理や分散システムのように、タイミング次第でまれにしか起きないバグを探すのに向く。代表的なツールは TLA+。

## yqコマンド

YAML 版の jq。YAML から値を取り出したり、書き換えたりする。

```bash
yq '.spec.replicas' deploy.yaml          # 値を取り出す → 2
yq -i '.spec.replicas = 3' deploy.yaml   # ファイルを書き換える
```

## Dependabot: ignore

Dependabot に「この更新は PR を作らなくていい」と伝える設定。すぐには上げられないメジャー更新の PR が溜まるのを防ぐ。

```yaml
# .github/dependabot.yml の updates の中
ignore:
  - dependency-name: "express"
    versions: ["5.x"]   # express 5 系への更新は無視
```

PR に `@dependabot ignore this major version` とコメントしても同じことができる。
