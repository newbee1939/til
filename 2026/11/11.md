## APMとは

- Application Performance Monitoring。アプリの中から性能を測る仕組み
- エンドポイントごとのレイテンシ・エラー率・スループットや、1 リクエストがどの処理（DB、外部 API）で時間を使ったかのトレースを見る
- インフラ監視（CPU・メモリ）では「遅い」としか分からないところを、「どのコードが遅いか」まで落とせる
- 例: Datadog APM、New Relic

## Multipath TCP（MPTCP）

> Multipath TCP provides the ability to simultaneously use multiple paths between peers.
> — RFC 8684
>
> 訳: Multipath TCP は、通信相手との間で複数の経路を同時に使えるようにする。

- 通常の TCP は 1 接続 = 1 経路（送信元 IP / ポートの組）。経路が切れると接続も切れる
- MPTCP は 1 接続の下に複数のサブフロー（例: Wi-Fi とモバイル回線）を張る。片方が落ちても接続が続く
- アプリから見ると普通の TCP と同じなので、アプリの変更は要らない

## XFF_IP

https://docs.cloud.google.com/armor/docs/rate-limiting-overview

> a unique key for each original client IP address, that is, the first IP address in the list of IPs specified in the X-Forwarded-For HTTP header.
>
> 訳: 元のクライアント IP ごとのキー。つまり X-Forwarded-For ヘッダーに並ぶ IP のうち先頭のもの。

- Cloud Armor のレート制限で「誰ごとに数えるか」（enforce-on-key）の 1 つ
- CDN やプロキシの後ろでは、LB から見える送信元 IP がプロキシの IP になる。そのままだと全員が 1 人として数えられるので、XFF の先頭（元のクライアント）で数える
- ヘッダーがない / 値が IP でない場合は、通常の IP キーにフォールバックする
- XFF の先頭はクライアントが自由に書けるので、偽装されうる点に注意
