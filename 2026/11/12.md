## AWS WAF Bot Control

参考: https://docs.aws.amazon.com/waf/latest/developerguide/aws-managed-rule-groups-bot.html

マネージドルールで、ボットの検査レベルを2段階から選ぶ。

- common
  - 自分からボットだと名乗るボット（検索クローラーなど）を検出
  - User-AgentやIPなどの既知の情報で判定する
- targeted
  - 人間のふりをする高度なボットも検出
  - ブラウザの調査（JSで実行環境を確認）やリクエストの振る舞いで判定する
  - 料金が高い

## CDPとは

Chrome DevTools Protocol。外部のプログラムからChromeを操作するためのプロトコル。

- Puppeteer / Playwright はこれでブラウザを動かしている
- ボットがヘッドレスブラウザを使うときもこれを使うので、Bot対策ではCDPの痕跡を検出に使う

## CAPTCHA

Completely Automated Public Turing test to tell Computers and Humans Apart。人間かボットかを判定するテスト（歪んだ文字や画像選択など）。

- AWS WAFでは、ルールのアクションに `CAPTCHA`（パズルを解かせる）と `Challenge`（裏でJSを実行させるだけ）がある

## Docker自前build

公開イメージをそのまま使わず、Dockerfileから自分でイメージをビルドすること。

- 良い点: 中身を把握できる、不要なものを削れる、脆弱性の修正を自分のタイミングで入れられる
- 失うもの: ベースイメージの更新やビルドを自分で回し続ける手間

## PaC（Policy as Code）

インフラのルール（「S3は公開しない」など）をコードで書いて、自動でチェックすること。

PlanとPaCの組み合わせ

- `terraform plan` の結果をJSONで出し、それをポリシーでチェックする
- 実際に作られる差分を `apply` の前に止められる

```bash
terraform plan -out=tfplan
terraform show -json tfplan > tfplan.json
checkov -f tfplan.json
```

## Checkov

https://www.checkov.io/

IaC（Terraform、CloudFormation、Kubernetesなど）の設定ミスを静的にチェックするOSS。PaCのツールの一つ。

## ログ配送

ログを発生元（アプリ・サーバー）から保存先や分析基盤（S3、CloudWatch Logs、Datadogなど）へ送ること。

- 代表的なツール: Fluent Bit、Vector、Amazon Data Firehose

## eBPF

Linuxカーネルを書き換えずに、カーネルの中で小さなプログラムを安全に動かす仕組み。

- 読み込む前にverifier（検証器）が「無限ループしない」「不正なメモリを触らない」を確認する
- 用途: 監視（bpftrace）、ネットワーク（Cilium）、セキュリティ（Falco）
