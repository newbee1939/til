## ⭐️Claude Code: /tui fullscreen

Claude Code の描画方式を切り替える。vim や htop と同じく、ターミナルの別画面（alternate screen）に描く。

- `/tui fullscreen` で有効、`/tui default` で戻す
- 入力欄が下に固定され、マウスでスクロールやクリックができる
    - これが大きい

https://code.claude.com/docs/en/fullscreen

## API サーバに Go を選ぶ理由（SNS の投稿より）

nginx の脆弱性が話題になったときの主張。要点は「部品が少ないほど、保守も脆弱性対応も楽」。

- 依存ライブラリを全部バイナリに含められる → コンテナに入れるのはバイナリ 1 つで済み、ほぼ空のイメージで動く
- 標準ライブラリだけで本番に耐える HTTP サーバが書ける → nginx や gunicorn を前に置かなくてよい
- 静的型付け、並列処理に強い、学習コストが低い

投稿者の結論: 今はバックエンドの第一候補は Go。最初の開発速度を優先するなら、フロントと揃えて TypeScript もあり。

## PHP の脆弱性への対応速度は構成で決まる（SNS の投稿より）

| 構成 | 対応 | かかる時間 |
| --- | --- | --- |
| コンテナ + PHP を最新に追随 + CI/CD とテストあり | Dockerfile のバージョンを上げてコミット → テスト → デプロイ | 最短 30 分 |
| VM / PHP が古い / テストなし | AMI 更新、古すぎてパッチが出なければメジャー更新とアプリ改修、手動で動作確認 | 数日〜数週間 |

差がつくのは、普段からバージョンを上げ続けているかどうか。後回しにしがちな作業だが、首相が SNS で注意を呼びかけるほどの事件になったので、上を説得しやすくなった。
