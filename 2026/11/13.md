## ⭐️TypeScript: 型は実行前に消える

型は「この値はこういう形」というメモ。読むのは人・`tsc`（ミスの検出）・エディタ（補完）だけで、実行する側は読まない。

```ts
function add(a: number, b: number) { return a + b }
add("1", 2) // tsc: エラー
```

ビルド後（型が消えただけ）:

```js
function add(a, b) { return a + b }
add("1", 2) // 普通に動いて "12" を返す
```

```
src/index.ts（型あり）
   ├─ tsc ──────────→ 型が合うか検査するだけ（何も出力しない）
   └─ ビルド（Vite）─→ 型を消して JS にまとめる（型は検査しない）
                         └─ JS を Workers が実行
```

- 検査（`tsc`）と変換（ビルド）は別の道。型エラーがあってもビルドは通る → CI で `lint` を別に回す
- `.d.ts` は「こう呼べる」という形だけを書いたファイルで、処理の中身はない。`Response` の中身は実行環境（workerd）に最初から組み込まれている

```ts
// .cloudflare/types/index.d.ts（抜粋）
declare var Response: {          // declare = 「どこかにある」と宣言するだけ
    new (body?: BodyInit | null, init?: ResponseInit): Response;
};
```

`new Response(...)` を書くと、`tsc` は上の形と照らし合わせるだけ。実行時は workerd の中にある本物の `Response` が動く。

### .ts と .d.ts

| | 中身 | ビルド後 |
|---|---|---|
| `.ts` | 型 + 処理 | 型が消えて `.js` になる |
| `.d.ts` | 型だけ | 何も残らない（`tsc` が読むだけ） |

自分のコードの型は `.ts` の中に一緒に書く。`.d.ts` が要るのは、TS で書かれていない（`.ts` がない）ものに型を付けるとき。

```
src/index.ts（自分のコード）
  export default { fetch() { return new Response(...) } }
    satisfies ExportedHandler
               │                         │
               │ 型を照合                  │ 型を照合
               ▼                         ▼
  .cloudflare/types/index.d.ts（型だけ）
               │ 中身はここにはない
               ▼
  workerd（C++）← Response の本物はここ。.ts は存在しない
```

`index.ts` は型を「使っている」だけで、`Response` / `ExportedHandler` を定義しているのは `.d.ts` のほう。

### cf workers types と tsc は両方要る

- `cf workers types`: `cloudflare.config.ts` から Workers 用の型（`Env`、`Response` など）を `.cloudflare/types/index.d.ts` に生成
- `tsc`: その型を使って型チェック
- 生成を飛ばすと `Cannot find name 'Response'`。`.cloudflare/` は gitignore なので CI では毎回生成が要る
